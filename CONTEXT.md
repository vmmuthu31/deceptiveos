# CipherNest — Domain Model & Glossary

## Core Concept
**CipherNest** is a cyber deception platform — it fights hackers by building smarter fake systems (honeypots) that trap, study, and outsmart attackers, including AI-powered attackers.

## Key Terms

### Honeypot
A fake server/service deliberately set up to lure attackers. When a hacker connects, they think they've found a real target, but everything they see is manufactured. CipherNest deploys three types:
- **Cowrie**: SSH/Telnet honeypot (fake terminal)
- **Dionaea**: Multi-protocol honeypot (HTTP, FTP, SSH)
- **CustomLLM**: AI-powered honeypot that uses an LLM to generate realistic responses

### Digital Twin Decoy
A honeypot that copies metadata from your REAL server (hostname, directory structure, software versions) so it looks identical. The "Living" part means it auto-updates as your real server changes. Unlike a static honeypot that looks fake after a week.

### Attacker DNA / Behavioral Fingerprint
A unique identity fingerprint built from HOW an attacker types — not what they type. Measures:
- **Command velocity**: How fast they type commands
- **Typo frequency**: How often they make mistakes (humans typo, AI agents rarely do)
- **Tool signature**: What tools/flags they use
- **Timing patterns**: Pauses between commands
- **Shannon entropy**: Randomness measure of their command strings

### MITRE ATT&CK
A globally-used knowledge base of attacker techniques (Tactics, Techniques, and Procedures — TTPs). Each attack method has a code like `T1005` (Data from Local System). CipherNest maps attacker behavior to these codes.

### Attacker Classification
CipherNest classifies attackers into three types:
- **ScriptKiddie**: Uses automated tools (nmap, sqlmap), low skill
- **HumanOperator**: Manual typing, interactive exploration, organic behavior
- **AIAgent**: Autonomous AI bot — fast, no typos, structured exploration, >120 char commands

### Steganography
Hiding data inside other data. CipherNest embeds invisible watermarks in lure documents:
- **Whitespace steganography**: Zero-width characters (`\u200B`, `\u200C`) encode binary data in text
- **Pixel canary**: 1x1 invisible image that pings back when the document is opened
- **Metadata tags**: Hidden HTML comments with tracking tokens

### Lure Document
A fake document (PDF, DOCX, XLSX, JSON, ENV) generated by AI to look like a real confidential file from a specific company/industry. Contains embedded watermarks. When an attacker steals and opens it, it "calls home" (beacon callback).

### Beacon Callback
When a watermarked lure document is opened, it sends an HTTP request back to CipherNest with the opener's IP, location, and user agent. This tracks where the stolen document ends up.

### STRK20 / Starknet
**Starknet** is a Layer 2 blockchain on Ethereum that uses zero-knowledge proofs for privacy and scalability. **STRK20** is a privacy standard on Starknet that allows shielded (hidden) token transfers.

### Zero-Knowledge Proof (ZKP)
A cryptographic proof that lets you prove something is true without revealing the underlying data. In CipherNest, it's used to pay bounties anonymously — the researcher gets paid without anyone knowing who they are.

### Shield / Unshield
- **Shield**: Convert public crypto tokens into hidden (shielded) tokens. Like converting cash to a numbered bank account.
- **Unshield**: Convert hidden tokens back to public tokens.

### GhostBounty
A bounty posted by a defender who has trapped an attacker. The defender funds it with shielded STRK tokens. A security researcher can claim it by submitting matching threat intelligence. The payment is anonymous via STRK20.

### Temporal Deception
Tricking attackers by adding realistic delays to responses. Different commands get different delays:
- `find/grep`: 1200-2600ms (simulates slow disk search)
- `openssl/gpg`: 700-1500ms (simulates crypto computation)
- `nmap/curl`: 400-1000ms (simulates network operations)
- Default: 80-330ms

This defeats AI scanners that detect honeypots by measuring response timing uniformity.

### Hash-Chain Audit Ledger
An append-only log where each entry (block) contains a SHA-256 hash of the previous block. If anyone tampers with an old entry, the entire chain breaks. Similar to blockchain but simpler. Used for SOC 2 compliance evidence.

### SOC 2 / ISO 27001 / GDPR
- **SOC 2 Type II**: US security compliance standard proving you have controls in place
- **ISO 27001**: International information security standard
- **GDPR Art. 32**: EU data protection law requiring data minimization and security

### STIX 2.1 / Sigma
- **STIX 2.1**: Standard format for sharing threat intelligence between security tools
- **Sigma**: Standard format for writing detection rules (like "alert if someone runs this command")

### Shannon Entropy
A mathematical measure of randomness. Used to analyze command strings — highly random commands might indicate automated tool usage, while low entropy suggests human typing.

### Levenshtein Distance
A measure of how many single-character edits (insertions, deletions, substitutions) are needed to change one string into another. Used to detect typos — if a command is 1-2 edits away from a known command, it's likely a typo.

### Air-Gap
A network security measure where a computer is physically isolated from unsecured networks. CipherNest's "air-gap mode" means it works with zero internet connection — all AI runs locally.

### Electron
A framework for building desktop apps using web technologies (HTML/CSS/JS). CipherNest uses it to create a desktop agent that runs locally on defender machines.

### napi-rs
A Rust library for building native Node.js modules. CipherNest plans to use it for high-performance metadata reading from the filesystem (reading directory structures, hostnames, etc.).

## Architecture Contexts
- **server/**: Backend logic — AI services, honeypot management, database, auth
- **client/**: Frontend UI — React components, pages, visual design
- **shared/**: Used by both — TypeScript types, validation schemas, utility functions
